# Implementation Plan — ID-Card Maker App (React + Vite, v1)

> **Build note (path correction):** runtime art is served from **`public/art/`** (URLs `/art/layers/…`,
> `/art/thumbnails/…`), NOT `public/assets/`. Vite's dev server reserves the `/assets/` URL prefix
> (its default `build.assetsDir`) and shadows `public/assets/**`, so those files 404 in dev. Wherever
> this doc says `assets/`, read `art/`.

## Context
`Docs/ProjectBrief.md` specifies a static, backendless **ID-card maker**: users assemble a card from
interchangeable full-canvas PNG layers + a few typed text fields, then download a 4K PNG. The card is a
**z-ordered stack of 3840×2420 transparent PNGs** (placement baked into each file → zero positioning code),
driven entirely by a **`manifest.json`** so that adding art never requires code changes.

Already done (prior steps): the 23 placeholder layer PNGs exist under `public/assets/layers/<Category>/`,
generated by [scripts/generate_placeholders.py](../scripts/generate_placeholders.py). This plan builds the
**application** that consumes them. **v1 scope:** core loop + **Reset** + **Randomize** + **shareable URL**.
**Styling:** SCSS using the **Enduring CSS (ECSS)** methodology.

## Tech stack & dependencies
- **App:** React 18 + Vite, JavaScript/JSX (no TypeScript — matches brief's `.jsx`/`.js` conventions).
- **deps:** `react`, `react-dom`, `html-to-image`, `@fontsource/quicksand` (self-hosted font so export
  fidelity is reliable; swappable).
- **devDeps:** `vite`, `@vitejs/plugin-react`, `sass` (Vite compiles `.scss` natively when present),
  `sharp` (build-time thumbnail downscaling).
- npm package name: `idcardmaker` (lowercase, cosmetic — per brief).

## Architecture & data flow
```
public/assets/layers/**          categories.config.mjs (z-order, select-type, text fields)
        \                                   /
         build-manifest.mjs  ── sharp ──►  public/assets/thumbnails/**  +  public/manifest.json
                                                        │ fetch
                                                        ▼
   useManifest() → manifest ─► useCardState(manifest, URL) ─► { selections, text }
                                                        │
                         ┌──────────────────────────────┼───────────────────────────┐
                         ▼                               ▼                            ▼
                  LayerPicker (thumbs)          CardStage (full-res layers      Toolbar (Download,
                  TextFieldsPanel                 in z-order + text on top)       Reset, Randomize, Copy link)
                                                        │ ref
                                                        ▼
                                          exportImage() → html-to-image toPng (4K)
```
The manifest is the single source of truth; components are generic over whatever categories/options it lists.

## Asset → manifest pipeline
**`scripts/categories.config.mjs`** — the one hand-edited registry (array order = z-order back→front):

```js
export const CANVAS = { width: 3840, height: 2420 };
export const CATEGORIES = [
  { id: "CardBase",      label: "Card",       select: "single", required: true  },
  { id: "PhotoBackdrop", label: "Backdrop",   select: "single", required: true  },
  { id: "BodyBase",      label: "Body",       select: "single", required: true  },
  { id: "Clothes",       label: "Clothes",    select: "single", required: true  },
  { id: "HairBack",      label: "Hair (back)",select: "single", required: false },
  { id: "Face",          label: "Face",       select: "single", required: true  },
  { id: "HairFront",     label: "Hair",       select: "single", required: true  },
  { id: "Glasses",       label: "Glasses",    select: "single", required: false },
  { id: "Headwear",      label: "Headwear",   select: "multi"                   },
  { id: "Badges",        label: "Badges",     select: "multi"                   },
  { id: "Stickers",      label: "Stickers",   select: "multi"                   },
  { id: "CardChrome",    label: "Frame",      select: "single", required: true, fixed: true },
];
export const TEXT_FIELDS = [ /* see table below */ ];
```

**`scripts/build-manifest.mjs`** — for each category in `CATEGORIES`: glob
`public/assets/layers/<id>/*.png`, sort by filename, build `options:[{ id: <stem>, src, thumb }]`; generate
a `THUMB_WIDTH`-wide thumbnail per file via **sharp** into `public/assets/thumbnails/<id>/` (skip if newer
than source); then write `public/manifest.json`. Warn on empty required categories or non-PascalCase names.
Idempotent; runs via `predev`/`prebuild` so a fresh clone/deploy just works. **Generating the manifest
*from* filenames is what prevents case/name drift** (brief's case-sensitivity constraint).

**`public/manifest.json`** (generated) schema:
```json
{
  "canvas": { "width": 3840, "height": 2420 },
  "categories": [
    { "id":"CardBase","label":"Card","select":"single","required":true,
      "options":[ {"id":"CardBasePink","src":"/assets/layers/CardBase/CardBasePink.png",
                   "thumb":"/assets/thumbnails/CardBase/CardBasePink.png"}, ... ] },
    { "id":"CardChrome","label":"Frame","select":"single","required":true,"fixed":true,"options":[ ... ] }
  ],
  "textFields": [ {"id":"name","label":"Name","x":2000,"y":480,"fontSize":110,"maxLength":24,"align":"left"}, ... ]
}
```

## Key mechanics
**Layered stage + scaling** — `CardStage` is a responsive box: `aspect-ratio: 3840/2420; width:100%`.
Render each manifest category in order; for the selected option(s) emit
`<img class="icm-Stage_Layer" style="z-index:<i>">` absolutely positioned `inset:0; width/height:100%`
(multi-select renders each selected option). Because placement is baked into the PNGs, no per-layer
coordinates are needed. A `ResizeObserver` tracks the stage's pixel width → `scale = width/3840`.

**Text on top** — for each `textFields` entry, a `<span class="icm-Stage_Text icm-Stage_Text-<id>">`
positioned `left:(x/3840*100)% ; top:(y/2420*100)%`, `font-size:(fontSize*scale)px`. Positions are %
(resolution-independent), font size scales with the stage. Empty value → render nothing.

**Export** (`src/utils/exportImage.js`) — primary path: await `document.fonts.ready`
+ all layer `<img>`s decoded, then `toPng(stageRef, { pixelRatio: EXPORT_WIDTH / stage.clientWidth,
cacheBust: true })` → always yields a 3840×2420 PNG regardless of display size (more robust than the
brief's fixed `pixelRatio:2`); trigger download as `${name||'id-card'}.png`. Fallback (brief's contingency,
implemented behind a try/catch or flag): manual `<canvas>` 3840×2420 — `drawImage(layer,0,0,3840,2420)` per
selected layer in z-order, then `fillText` each field at its canvas coords — fully deterministic if
html-to-image shows font/sharpness issues.

**State** (`src/hooks/useCardState.js`) — `selections: Record<catId, string|null|string[]>`
and `text: Record<fieldId,string>`. Init from URL (`parseParamsToState`, validated against manifest) else
defaults (1st option for required single; `null` for optional single; `[]` for multi). Actions:
`setSingle`, `clearSingle`, `toggleMulti`, `setText`, `reset`, `randomize`. A debounced effect writes state
to the URL via `history.replaceState`.

**Shareable URL** (`src/utils/urlState.js`) — readable params: single =
`?CardBase=CardBasePink`, multi = `?Headwear=HeadwearCapRed,HeadwearBowBlue`, text =
`?name=...` (URL-encoded). Parser ignores unknown categories/option-ids so links survive asset changes.
Toolbar "Copy link" writes `location.href` to the clipboard.

**Lazy-load** — pickers use small generated thumbnails (`<img loading="lazy">`); full-res 4K layers mount
only when selected, so they load on demand (satisfies brief's lazy-load requirement).

## Styling — SCSS + Enduring CSS (ECSS)
- **Namespace** `icm`. Class grammar: `.icm-Module_childNode-variant` (Module PascalCase, child after `_`,
  state/variant after `-`). Examples: `.icm-Stage`, `.icm-Stage_Layer`, `.icm-Picker_Option-selected`,
  `.icm-Bar_Button-primary`.
- **One `.scss` module per component**, co-located and imported for side effects
  (`import './CardStage.scss'`). Isolation comes from the **naming convention**, not CSS-Modules tooling.
- **Shared partials** in `src/styles/` (`_settings`, `_mixins`, `_base`) consumed via modern Sass
  `@use` (e.g. `@use '../styles/settings' as s;` then `s.$ink`). `_settings.scss` is the single source
  of truth for colors/spacing/breakpoints.
- **ECSS conventions:** flat low-specificity selectors, one class per node, minimal nesting, no id/element
  structural selectors, variants expressed as explicit `-variant` classes; duplication preferred over
  fragile abstraction.

Example `CardStage.scss`:
```scss
@use "../styles/settings" as s;
.icm-Stage { position: relative; width: 100%; aspect-ratio: #{s.$canvas-w} / #{s.$canvas-h};
             background: transparent; }
.icm-Stage_Layer { position: absolute; inset: 0; width: 100%; height: 100%; pointer-events: none; }
.icm-Stage_Text  { position: absolute; color: s.$ink; font-family: s.$font; line-height: 1; white-space: nowrap; }
```

  `scripts/preview.png`. (Layer masters in `public/assets/layers/` stay committed.)

## Verification (end-to-end)
1. `npm install` → `npm run dev` (predev builds thumbnails + manifest) → card renders with defaults.
2. Switch single-select options → preview swaps; set Glasses/HairBack to **None** → layer disappears.
3. Toggle Headwear/Badges/Stickers → multiple appear at their distinct baked positions.
4. Type Name/Birthday/Class/Nationality → text appears above the chrome underlines.
5. URL updates live; **Copy link**, open in a new tab → identical card restored. **Reset** → defaults;
   **Randomize** → a random valid card.
6. **Download** → open the PNG: exactly **3840×2420**, all chosen layers + text composited, transparent
   outside the card's rounded corners.
7. Drop a new `public/assets/layers/Face/FaceMystery.png`, rerun `npm run assets` → it appears as a new
   Face option **with no code change** (proves the manifest-from-filenames goal).
8. `npm run build` succeeds; `npm run preview` serves the production build.

## Out of scope (future)
- Granular, mixable Face/Hair sub-parts (v1 = one full expression / single hair layer).
- A Vite plugin to watch `layers/` and regenerate the manifest live (v1 uses the `predev`/`prebuild` step).
- Public gallery (would need a DB); print crop-marks/bleed export; multiple card templates; i18n.
